# Исследование времени сборки C++-сервиса на userver

Проект посвящён анализу времени компиляции сервиса на C++ с использованием
userver и проверке гипотезы об ускорении сборки с помощью precompiled headers
(PCH).

## Что исследовалось

По данным Clang Build Analyzer значительная часть затрат компиляции связана
с Frontend. Проверялась гипотеза, что предварительная компиляция выбранных
заголовков позволит уменьшить эти затраты.

Сравнивались три конфигурации:

- `NONE` — без PCH;
- `COMPONENT` — PCH для `userver/components/component.hpp`;
- `TWO_HEADERS` — PCH для `component.hpp` и
  `hello_service.usrv.pb.hpp`.

## Окружение

- Docker-образ `ghcr.io/userver-framework/ubuntu-22.04-userver`,
  закреплённый digest из тестового задания.
- Clang 14, Release, Ninja.
- Флаг компиляции `-ftime-trace`.
- Ограничения контейнера: 4 CPU и 8 ГиБ памяти.
- Кэширование `ccache` отключено.
- Clang Build Analyzer: commit
  `55447756ff8af2f87e4a315f2ba637b9380363ea`.

## Результаты

Для каждой конфигурации выполнено по три чистые сборки.

| Конфигурация | Время запусков, с | Медиана, с |
|---|---|---:|
| Без PCH | 32,12; 30,42; 34,83 | 32,12 |
| PCH одного заголовка | 31,99; 32,36; 30,18 | 31,99 |
| PCH двух заголовков | 33,09; 32,99; 30,61 | 32,99 |

Медианное агрегированное время Frontend по данным Clang Build Analyzer
составило 41,7 с без PCH, 38,7 с с одним заголовком и 36,7 с с двумя.
При этом медианное реальное время полной сборки практически не изменилось
с одним заголовком и увеличилось при использовании двух.

Таким образом, наблюдается сокращение затрат Frontend, но заметного
ускорения полной сборки не получено. При трёх запусках на конфигурацию
разброс результатов не позволяет уверенно судить о небольших различиях
wall-clock времени.

Времена Frontend и Backend в отчётах анализатора агрегированы по компиляциям
и не являются длительностью сборки по часам.

## Как воспроизвести эксперимент

Требуются Linux, Docker с доступом к запуску контейнеров и подключение
к интернету для загрузки зависимостей и исходников анализатора.

Из корня репозитория выполните:

    ./scripts/run-experiments.sh

По умолчанию скрипт выполняет по три запуска каждой конфигурации.
Для пробного запуска с одним повтором можно выполнить:

    REPEATS=1 ./scripts/run-experiments.sh

Скрипт запускает закреплённый Docker-образ с ограничениями ресурсов,
настраивает и собирает сервис для каждой конфигурации, измеряет wall-clock
время и запускает Clang Build Analyzer.

Новые результаты сохраняются в `results/reproducible-<timestamp>/`.
Они включают логи сборки, текстовые отчёты анализатора, бинарные трейсы
и измеренное время каждой сборки. Каталог `results/` исключён из Git.

## Структура репозитория

- `benchmark_service/` — исходный код и конфигурация CMake сервиса;
- `scripts/run-experiments.sh` — скрипт воспроизведения измерений;
- `clang-build-analyzer/reports/` — текстовые отчёты и бинарные трейсы для трёх конфигураций.
  Оставлено по одному репрезентативному трейсу на режим; wall-clock в таблице — медиана трёх запусков.
